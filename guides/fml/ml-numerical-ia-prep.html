1.1 What is ML?

Definition

ML is a set of algorithms that can learn to perform tasks such as prediction and classification effectively using data.

Two classic definitions worth knowing by name for the exam:

"A computer program is said to learn from experience E with respect to some class of tasks T, and performance measure P, if its performance at tasks in T, as measured by P, improves with experience E." — Tom Mitchell (1997)
"A field of study that gives computers the ability to learn without being explicitly programmed." — Arthur Samuel (1959)
Exam tip — Mitchell's definition, in T/P/E form

Mitchell's definition is often tested by asking you to identify T (Task), P (Performance measure), and E (Experience) for a given scenario. For the spam-filter example later in this lecture: T = flagging spam for new emails, P = accuracy (ratio of correctly classified emails), E = the training data (examples of spam and non-spam/"ham" emails).

1.2 Need for Machine Learning

Why ML became possible and necessary
  • High volume of available data — there's simply far more data to learn from than ever before.
  • Cost of storage has reduced — it's now cheap to keep all that data around.
  • Unavailability of complex algorithms (historically) — hand-coding rules for genuinely complex problems just doesn't scale.

Important objectives of Machine Learning:

  • To process archived data for organizations
  • To make better decisions
  • To design new products
  • To improve business processes to develop decision support systems

1.3 Introduction to Machine Learning

The human-learning analogy

In the real world, we are surrounded by humans who can learn everything from their experiences with their learning capability, and we have computers or machines which work on our instructions. But can a machine also learn from experiences or past data like a human does? So here comes the role of Machine Learning.

Machine Learning is said to be a subset of artificial intelligence that is mainly concerned with the development of algorithms which allow a computer to learn from the data and past experiences on their own.

How an ML system actually behaves
  • A Machine Learning system learns from historical data, builds prediction models, and whenever it receives new data, predicts the output for it.
  • The accuracy of the predicted output depends upon the amount of data — a huge amount of data helps build a better model that predicts more accurately.
  • Suppose we have a complex problem where we need to perform predictions. Instead of writing code for it, we feed the data to generic algorithms, and with the help of these algorithms, the machine builds the logic as per the data and predicts the output.

1.4 What is Artificial Intelligence (AI)? AI vs. ML

Definition

AI can be concisely described as the effort to automate intellectual tasks normally performed by humans. AI is a general field that encompasses machine learning and deep learning — but AI also includes many more approaches that may not involve any learning at all (e.g. hardcoded rule systems).

The historical story: Symbolic AI → Machine Learning

Symbolic AI was the dominant paradigm in AI from the 1950s to the 1980s, reaching peak popularity during the expert-systems boom of the 1980s. Early chess programs only involved hardcoded rules crafted by programmers, and did not qualify as machine learning. For a long time, most experts believed that human-level AI could be achieved simply by having programmers handcraft a sufficiently large set of explicit rules for manipulating knowledge stored in explicit databases.

Symbolic AI proved suitable for well-defined, logical problems such as playing chess. But it turned out to be intractable for more complex, "fuzzy" problems — image classification, speech recognition, natural language translation. A new approach arose to take symbolic AI's place: machine learning.

Machine learning looks at the input data and the corresponding answers, and figures out what the rules should be. A machine learning system is trained rather than explicitly programmed — presented with many examples relevant to a task, it finds statistical structure in those examples that eventually lets it come up with rules for automating the task.

A fun historical aside

The origins of chess are debated, but most historians agree that the game's ancestor, chaturanga, originated in India around the 6th century AD.

ML vs. classical statistics
  • Unlike statistics, machine learning tends to deal with large, complex datasets (such as a dataset of millions of images, each with tens of thousands of pixels) — classical statistical analysis, such as Bayesian analysis, would be impractical at that scale.
  • Machine learning — and especially deep learning — exhibits comparatively little mathematical theory and is fundamentally an engineering discipline.

1.5 Machine Learning: a New Programming Paradigm

The paradigm shift

Traditional programming: you write explicit rules and feed them, together with data, into a program, to get answers out.

Machine learning flips this around: you feed in data and the answers (expected outputs), and the system produces the rules — which can then be applied to new data.

To do machine learning, we need three things
  1. Input data points — e.g. for speech recognition, sound files of people speaking; for image tagging, pictures.
  2. Examples of the expected output — e.g. human-generated transcripts for speech recognition; tags like "dog," "cat" for image tagging.
  3. A way to measure whether the algorithm is doing a good job — necessary to determine the distance between the algorithm's current output and its expected output. This measurement is used as a feedback signal to adjust the way the algorithm works. This adjustment step is what we call learning.
Motivation

Over the past two decades, Machine Learning has become one of the mainstays of information technology. With the ever-increasing amounts of data becoming available, there is good reason to believe that smart data analysis will become more pervasive as a necessary ingredient for technological progress.

1.6 Case Study: the Spam Filter

This is the running example the course uses to make "why ML?" completely concrete — the same problem, solved two ways.

Setting up the problem, in Mitchell's T/P/E language
  • A spam filter is given examples of spam emails (e.g. flagged by users) and examples of regular ("ham") emails, and learns to flag spam.
  • The examples the system uses to learn are the training set; each training example is a training instance (or sample).
  • Task T: flag spam for new emails. Experience E: the training data. Performance measure P: needs to be defined — a common choice is the ratio of correctly classified emails, called accuracy, often used in classification tasks.
Attempt 1 — traditional programming

What does spam typically look like? You'd notice that some words or phrases (like "4U," "credit card," "free," "amazing") tend to come up a lot in the subject line — and perhaps other patterns in the sender's name, the email body, etc.

  1. Notice these patterns.
  2. Write a detection algorithm for each pattern noticed; the program flags an email as spam if enough of these patterns are detected.
  3. Test the program, and repeat steps 1–2 until it's good enough to launch.
The problem

The program will likely become a long list of complex rules — hard to maintain.

Attempt 2 — the Machine Learning approach

A spam filter based on ML techniques automatically learns which words and phrases are good predictors of spam, by detecting unusually frequent patterns of words in the spam examples compared to the ham examples. The program is much shorter, easier to maintain, and most likely more accurate.

The real payoff — automatically adapting to change

If spammers keep working around your spam filter, a traditional rule-based system needs new rules written forever. Example: if spammers notice all their emails containing "4U" are blocked, they switch to "For U" instead. A traditional filter would need to be manually updated to catch "For U." An ML-based filter automatically notices that "For U" has become unusually frequent in emails flagged as spam by users, and starts flagging them — without any intervention from you.

1.7 Other Applications, and Why Use ML

Problems too complex for hand-written rules

Machine Learning also shines for problems that are either too complex for traditional approaches, or have no known algorithm. Example — speech recognition: to distinguish the words "one" and "two," you might notice "two" starts with a high-pitch sound ("T") and hardcode an algorithm around that. But this won't scale to thousands of words, spoken by millions of different people, in noisy environments, across dozens of languages. The best solution: write an algorithm that learns by itself, given many example recordings of each word.

Machine Learning can help humans learn

ML algorithms can be inspected to see what they've learned (though for some algorithms this can be tricky). Example: once a spam filter is trained on enough spam, you can inspect it to reveal the list of words and word-combinations it believes are the best predictors of spam — sometimes revealing unsuspected correlations or new trends. Applying ML to dig through large amounts of data to discover non-obvious patterns is called data mining.

Why Use Machine Learning? — Summary

Machine Learning is great for:

  • Problems for which existing solutions require a lot of fine-tuning or long lists of rules — one ML algorithm can often simplify the code and perform better than the traditional approach.
  • Complex problems for which a traditional approach yields no good solution — the best ML techniques can perhaps find one.
  • Fluctuating environments — an ML system can adapt to new data.
  • Getting insights about complex problems and large amounts of data.
Examples of applications in diverse fields

Machine learning is a growing technology used to mine knowledge from data (the "data mining" field). Wherever data exists, things can be learned from it — and whenever there's an excess of data, the mechanics of learning must be automatic. Applications emerge not from ML experts, nor from the data alone, but from people who work with the data and the problems it arises from.

1.9 Supervised Learning

Definition
  • Uses labelled data — the training data fed to the algorithm includes the desired solution, called labels.
  • Two main categories: Classification and Regression.
  • ML has two important stages: Training and Testing. In training, the algorithm takes a labelled dataset (input) and starts learning; after training, the samples are processed and the model is generated. In testing, the constructed model is tested with test samples (data the model hasn't seen).
Classification Model
  • Input attributes are independent variables; target attributes are dependent variables.
  • Output is a discrete value — separate groups, e.g. yes/no, cat/dog, spam/not spam.
  • The relationship between dependent (target) and independent (input) variables is represented in a structure called classification.
  • Important classification algorithms: Logistic Regression, Support Vector Machine, KNN, Naive Bayes.
Regression Model
  • Unlike classification, the output is a continuous value — real numbers within a range, e.g. price, temperature, weight.
  • Important regression algorithms: Linear Regression, Decision Tree, Random Forest, Gradient Boosting.
Formalising supervised learning as function approximation

Goal: predict \(y\) from \(x\). Given a labelled set of input-output pairs, map input \(x\) to output \(y\).

Given: a training set \(\{(x_i,y_i)\ |\ i=1\dots n\}\). Find: a good approximation to \(f:X\to Y\) where \(y\in\{1,\dots,C\}\).

  • Classification — \(y\) is categorical.
  • Regression — \(y\) is a real value.

Formalising: \(y=f(x)\) for some unknown function \(f\); the goal of learning is to estimate \(f\), given a labelled training set, and then make predictions using \(\hat y=\hat f(x)\).

Generalization means making good predictions on novel inputs (data the model hasn't seen before) — not just memorising the training data. Examples: spam detection, digit recognition, stock prices.

A little history — where "supervised learning" comes from

The supervised learning strategy consists of having available the desired outputs for a given set of input signals — each training sample is composed of the input signals and their corresponding outputs. This requires a table of input/output data, also called an attribute/value table, which represents the process and its behaviour. It is from this information that the learning system formulates a "hypothesis" about the system being learned. Donald Hebb proposed the first supervised learning strategy in 1949, inspired by neurophysiological observations.

Mechanically: the network is trained by providing it with input and matching output patterns (usually from an external "teacher"). The network processes the inputs and compares its resulting outputs against the desired outputs. Errors are then propagated back through the system, causing it to adjust its weights. This repeats over and over as weights are continually refined — the set of data enabling this training is the training set. Example architectures: Perceptron, Feed-forward networks, Radial Basis Function networks, Support Vector Machines.

1.10 Unsupervised Learning

Definition — "Learning without a Teacher"
  • Self-organized learning — no external teacher or critic oversees the learning process.
  • The system is supposed to discover statistically salient features of the input population.
  • Unlike supervised learning, there is no a priori set of categories into which the patterns are to be classified — the system must develop its own representation of the input stimuli.
  • All similar input patterns are grouped together as clusters; if a matching input pattern isn't found, a new cluster is formed.
  • Example architectures: Self-organizing maps, Hopfield networks.
A biological analogy worth remembering

The slides use the analogy of "how a fish or tadpole learns" — grouping similar experiences together without anyone labelling them, purely by noticing statistical regularities in what it encounters.

Block diagram of unsupervised learning — no feedback signal, just the environment's state feeding the learning system.

1.11 Reinforcement Learning

When is reinforcement learning used?

If less information is available about the target output values (critic information), learning based on this critic information is called reinforcement learning, and the feedback sent is called the reinforcement signal. Crucially, the feedback here is only evaluative (how good/bad was that?) and not instructive (it doesn't tell you the correct answer, unlike supervised learning's labels).

Block diagram of reinforcement learning — the environment provides state and a primary reinforcement signal; a "critic" turns this into a heuristic reinforcement signal that shapes the learning system's actions.

1.14 Linear Regression — Introduction

Definition

Linear Regression is a simple and powerful model approach for predicting a numeric response from a set of one or more independent variables. It models the relationship between a dependent variable \(y\) and one or more independent variables \(X\). The goal is to find a line (or hyperplane) that best fits the data points by minimizing the error between predicted and actual values.

Dependent and Independent Variables:

  • \(y\) — the variable we wish to predict: dependent, Response, or Target variable.
  • \(X\) — the variable(s) used to predict \(y\): independent, predictor variable(s).
Three forms of Linear Regression, based on the input data
  • Simple Linear Regression — one independent variable.
  • Multi(ple) Linear Regression — more than one independent variable.
  • Polynomial Regression — fits a curve rather than a straight line (covered in Lecture 3).
Reading the regression equation

\[ y = mx + c \]

  • \(y\) — the target or output value you want to predict.
  • \(x\) — the input feature or data point you use to make the prediction.
  • \(m\) — the slope of the line, showing how much \(y\) changes when \(x\) goes up by one unit.
  • \(c\) — the y-intercept, the value of \(y\) when \(x=0\).

1.15 Simple Linear Regression Numerical

Theory

We're fitting a straight line $\hat{y} = mx + c$ through a set of $(x_i, y_i)$ points, choosing $m$ (slope) and $c$ (intercept) to minimize the squared error between actual $y$ and predicted $\hat y$.

The closed-form (calculus-derived) formulas are:

$$ m = \frac{\sum_{i=1}^{n}(x_i - \bar x)(y_i - \bar y)}{\sum_{i=1}^{n}(x_i - \bar x)^2} \qquad\qquad c = \bar y - m\bar x $$

where $\bar x$ and $\bar y$ are the means of $x$ and $y$.

Error / goodness-of-fit metrics — these almost always follow the slope/intercept calculation in an exam question:

$$ SS_{tot} = \sum (y_i - \bar y)^2 \qquad SS_{res} = \sum (y_i - \hat y_i)^2 $$ $$ MSE = \frac{SS_{res}}{n} \qquad RMSE = \sqrt{MSE} \qquad R^2 = 1 - \frac{SS_{res}}{SS_{tot}} $$

$R^2$ tells you what fraction of the variation in $y$ is "explained" by $x$ — closer to 1 is a better fit.

1.16 Multiple Linear Regression Numerical

Theory

With more than one input feature, we fit $y = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + \dots + \beta_p x_p$. The closed-form solution (no iteration needed) is the Normal Equation:

$$ \hat\beta = (X^TX)^{-1}X^Ty $$

where $X$ is the design matrix — every row is one data point, with a leading column of 1's for the intercept $\beta_0$.

The five calculation steps every time:

  1. Build $X$ (add the column of 1's) and the target vector $y$.
  2. Compute $X^T$ (transpose).
  3. Compute the product $X^TX$ (a square matrix).
  4. Invert $X^TX$ to get $(X^TX)^{-1}$.
  5. Multiply: $\hat\beta = (X^TX)^{-1}(X^Ty)$.

Lecture 2

Linear Regression Using Gradient Descent

Lecture 1 solved for the regression line two ways — the Normal Equation's closed form, and a first taste of Stochastic Gradient Descent. This lecture goes deep on the second method: why it exists, exactly how it updates its coefficients, and a full derivation from first principles.

2.1 Normal Equation vs. Gradient Descent

Two fundamentally different ways to fit a line
  • Normal Equation — linear regression using the normal equation gives a closed-form solution, using calculus to find the minimum of a function directly.
  • Gradient Descent — an iterative optimization algorithm that steadily alters the parameters, minimizing the cost function step by step.
Advantages of each method

Normal Equation: computationally efficient for small-to-medium datasets with a simple linear model.

Gradient Descent:

  • Scalability — can efficiently handle large datasets that may not fit in memory, processing data in batches.
  • Flexibility — applies to a wide range of ML models: linear regression, logistic regression, neural networks, and more.
  • Ability to handle complex models — can optimize models with a large number of parameters or nonlinear relationships that may be difficult to solve using the normal equation.

2.2 Stochastic Gradient Descent — the mechanics

Definition

Stochastic Gradient Descent (SGD) can be used to learn (search for) the coefficients of a simple linear regression model by minimizing the error on a training dataset. Gradient Descent is the process of minimizing a function by following the gradients (slope) of the cost function — this requires knowing both the cost and its derivative, so that from a given point we know the gradient and can move in that direction (e.g. downhill, towards the minimum).

How the algorithm works, step by step
  • Each training instance is shown to the model one at a time.
  • The model makes a prediction for that training instance.
  • The error is calculated.
  • The model is updated to reduce the error for the next prediction.

In each iteration, the coefficients — called weights (w) in ML language — are updated using:

\[ w = w - \alpha\cdot\text{delta} \]

  • \(w\) — the coefficient/weight being optimized.
  • \(\alpha\) — the learning rate we must configure (e.g. 0.1).
  • delta (or gradient) — the error for the model on the training data, attributed to that weight.
Two vivid analogies worth remembering

Hiking down a mountain: the perfect analogy for gradient descent — imagine a valley and a person with no sense of direction trying to reach the bottom. He goes down the slope, taking large steps when the slope is steep and small steps when it's less steep, deciding his next position based on his current one, and stops when he reaches the bottom (the goal).

A large bowl: think of the cost function's plot as a large bowl. A random position on the bowl's surface is the cost of the current coefficient values. The bottom of the bowl is the cost of the best coefficients — the minimum. The goal is to keep trying different coefficient values, evaluating their cost, and selecting new ones with slightly lower cost. Repeating this enough times leads to the bottom.

The general Gradient Descent procedure
  1. The derivative of the cost is calculated — the slope of the function at a given point, telling us the direction (sign) to move the coefficients to get a lower cost next time: \(\text{delta}=\text{derivative(cost)}\).
  2. Now that we know which direction is "downhill," update the coefficients: \(\text{coefficient} = \text{coefficient} - (\alpha\times\text{delta})\).
  3. Repeat until the cost is 0.0, or no further improvement can be achieved.
Where do the "coefficients" come from, in general?

The goal of all supervised ML algorithms is to best estimate a target function \(f\) that maps input data \(X\) onto output variables \(Y\) — this describes all classification and regression problems. Some algorithms have coefficients that characterize their estimate of \(f\); different algorithms have different representations and coefficients, but many require an optimization process to find the coefficients giving the best estimate. Common algorithms with coefficients optimizable via gradient descent: Linear Regression and Logistic Regression.

The cost function evaluates the coefficients by calculating a prediction for every training instance, comparing predictions to actual outputs, and calculating a sum or average error — such as the Sum of Squared Residuals (SSR) for linear regression. The cost is calculated over the entire training dataset.

Why "stochastic"? Batch vs. Stochastic Gradient Descent

Gradient descent can be slow on very large datasets, because one iteration requires a prediction for every instance in the training set — this takes a long time with millions of instances (this full-dataset version is called Batch Gradient Descent). Stochastic Gradient Descent is a variation where the coefficient update happens after each individual training instance, rather than waiting until the end of a full batch.

Full derivation — the SGD update equation for simple linear regression

Dataset with input features \(x\) and target values \(y\). The model predicts \(y=w\cdot x+b\), where \(w\) is the weight (slope) and \(b\) the bias (intercept).

Step 1 — define the Mean Squared Error (MSE) loss function:

\[ L(w,b) = \frac1N\sum_{i=1}^N\big(y_i-(w\cdot x_i+b)\big)^2 \]

where \(N\) is the number of training examples, \(x_i\) is the \(i\)th feature, \(y_i\) is the true label for the \(i\)th training example.

Step 2 & 3 — compute the gradient (the partial derivatives of \(L\) with respect to \(w\) and \(b\)):

\[ \frac{\partial L}{\partial w} = -\frac2N\sum_{i=1}^Nx_i\cdot\big(y_i-(w\cdot x_i+b)\big) \qquad \frac{\partial L}{\partial b} = -\frac2N\sum_{i=1}^N\big(y_i-(w\cdot x_i+b)\big) \]

(Setting both derivatives to zero and solving simultaneously would give the closed-form Normal Equation solution directly — this is exactly where the two methods connect.)

Step 4 — the Gradient Descent perspective: rather than solving the derivatives analytically, update \(w\) and \(b\) iteratively in the direction opposite the gradient:

\[ w = w-\alpha\cdot\frac{\partial L}{\partial w} \qquad b = b-\alpha\cdot\frac{\partial L}{\partial b} \]

Connecting this back to the exam-style update rule

For a single training instance (the stochastic case, \(N=1\)), \(\partial L/\partial w\) simplifies to \(-2\cdot x\cdot\text{error}\) and \(\partial L/\partial b\) to \(-2\cdot\text{error}\) (where \(\text{error}=p(i)-y(i)\)). Absorbing the constant \(-2\) into the learning rate \(\alpha\) recovers exactly the simpler rule used throughout this course: \(B_0^{(t+1)}=B_0^{(t)}-\alpha\cdot\text{error}\), \(B_1^{(t+1)}=B_1^{(t)}-\alpha\cdot\text{error}\cdot x\).

2.2 Linear Regression via Gradient Descent (SGD) Numerical

Theory

Instead of solving for coefficients in closed form, Stochastic Gradient Descent starts with $B_0=0, B_1=0$ and updates them one training example at a time, nudging them a little closer to the optimum on each pass:

$$ p(i) = B_0 + B_1\cdot x(i) \qquad \text{error} = p(i)-y(i) $$ $$ B_0^{(t+1)} = B_0^{(t)} - \alpha \cdot \text{error} \qquad B_1^{(t+1)} = B_1^{(t)} - \alpha \cdot \text{error}\cdot x(i) $$

$\alpha$ is the learning rate (a small constant like 0.01 or 0.1). One full pass through all training points is called an epoch.

Exam tip: the question will almost always give you a small dataset (4–5 points), an initial $B_0, B_1$ (usually both 0), a value of $\alpha$, and ask you to hand-compute 1–2 iterations or one full epoch, showing $p(i)$, error, and the updated $B_0, B_1$ at every step.

Applying Gradient Descent — practical tips from your slides

Preparing data, and reading the diagnostics
  • Plot Cost vs. Iteration — collect and plot the cost each iteration. A well-performing run shows cost decreasing every iteration; if it doesn't, try reducing the learning rate.
  • Learning rate — a small value like 0.1, 0.001, or 0.0001; try different values and see what works best.

Model Behaviour — Parametric Models, Overfitting, Bias-Variance, and Polynomial Regression

Before going further into new algorithms, this lecture pauses to ask a deeper question: what makes a model good, in a way that generalises beyond the exact data it was trained on? This is arguably the most conceptually important lecture in the course — every later algorithm gets judged against these ideas.

3.1 Parametric vs. Non-Parametric ML Models

Definitions

Parametric models assume a specific functional form for the relationship between input and output variables. They summarize the data using a fixed number of parameters, regardless of the dataset's size. Examples: Linear Regression, Logistic Regression, Naive Bayes.

Non-parametric models do not assume a predefined functional form. They are highly flexible and can adapt to complex patterns in data. Examples: k-Nearest Neighbors (KNN), Decision Trees, Support Vector Machines.

Worked illustration

Linear regression models the relationship as \(y=b_0+b_1x_1+b_2x_2\) — here \(b_0,b_1,b_2\) are fixed parameters learned from the data, regardless of whether you have 100 or 100,000 data points (that's what makes it "parametric"). KNN, by contrast, predicts the output for a new point based on the majority class of its \(k\) nearest neighbours in the actual stored data — there's no fixed small set of parameters standing in for the whole dataset.

from sklearn.neighbors import KNeighborsClassifier

3.2 Generalization, Overfitting & Underfitting

Generalization — the central question of this whole lecture

How well does a learned model generalize from the data it was trained on, to a new test set? A model is trained on a training set (labels known), and its real value is judged on a test set (unseen data) — e.g. training on labelled photos of fruits and animals, then testing on new, unlabelled photos of the same categories.

What is overfitting?

Overfitting occurs when a machine learning algorithm begins to memorize the training data rather than learning the underlying patterns — typically because the model is too complex for the data it's modeling. This leads to poor performance on new data, since the algorithm can't generalize beyond what it has memorized.

What is underfitting?

Underfitting occurs when a model is not complex enough — often because it isn't given enough data to learn from. As a result, it fails to learn the generalizable patterns and performs poorly on both the training data and new data.

What is a "good fit"?

A good fit is a model that accurately predicts the output of new data. The goal of machine learning is to build models that generalize well — meaning a low error rate on a test set of unseen data, not just a low error rate on the training data.

3.3 The No Free Lunch Theorem

The idea (and the pun in the name)

The slides illustrate this with a cartoon of a vending machine advertising "Free Lunch — $10.00" — a joke on the theorem's name. The actual content of the No Free Lunch theorem: no single machine learning algorithm works best for every problem. The assumptions that make one algorithm perform well on one type of data (e.g. linear regression's assumption of a linear relationship) can make it perform poorly on data that violates those assumptions. There's no universally-best model — the "lunch" of a perfect one-size-fits-all algorithm is never actually free; you always pay for good performance with assumptions that could be wrong for a different dataset.

3.4 Bias and Variance

The error decomposition

A model's error can be split into reducible and irreducible parts.

  • Reducible error — split further into bias ("error due to squared bias") and variance ("error due to variance").
  • Irreducible error — the error we cannot remove with our model, caused by things outside our control, like statistical noise in observations (also called irreducible noise).

Bias — the difference between model predictions and the training data (on one set). Variance — the difference between model predictions and their expected value, over all possible training sets.

3.5 Polynomial Regression

What is Polynomial Regression?

Polynomial Regression models the relationship between independent and dependent variables as an \(n\)th degree polynomial. It's a special case of Linear Regression, where we fit a polynomial equation to data with a curvilinear relationship. A Quadratic Equation is a polynomial of the 2nd degree — but the degree can increase to any \(n\).

Assumptions of Polynomial Regression
  • The dependent variable's behaviour can be explained by a linear or curvilinear additive relationship with a set of \(k\) independent variables.
  • The relationship between the dependent variable and any independent variable is linear or curvilinear (specifically polynomial).
  • The independent variables are independent of each other.
  • The errors are independent, normally distributed with mean zero and constant variance (the OLS — Ordinary Least Squares — assumptions).
Why do we need Polynomial Regression?

Consider Simple Linear Regression: we build a model and find it performs very badly. Looking at the gap between the actual values and the best-fit line, we notice the actual data has some kind of curve — the straight line is nowhere near cutting through the mean of the points. This is exactly where Polynomial Regression comes in: it predicts a best-fit line that follows the pattern (curve) of the data.

Polynomial regression does not require the relationship between independent and dependent variables to be linear — this is the key difference from ordinary Linear Regression. It's generally used when Linear Regression fails to describe the data well.

A trade-off worth remembering

As we increase the degree of the polynomial, model performance tends to increase — but increasing the degree also increases the risk of over-fitting (as well as, at very low degrees, under-fitting). This connects directly back to Section 3.4's bias-variance trade-off: a higher-degree polynomial has lower bias (it can bend to fit the training data closely) but higher variance (small changes in the data swing the fitted curve a lot).

How to find the right degree
  1. Forward Selection — increase the degree until it is significant enough to define the best possible model.
  2. Backward Selection — decrease the degree until it is significant enough to define the best possible model.
The polynomial function, and special cases you should recognise

A polynomial is a function \(f(x)=c_0+c_1x+c_2x^2+\cdots+c_nx^n\), where \(n\) is the degree and \(c_i\) are coefficients.

  • Degree 0 is just a constant. Performing polynomial regression of degree 0 on a dataset returns a single constant value — the mean average of the data (which makes sense: the average is an approximation of all the data points at once).
  • Degree 1 is ordinary Linear Regression: \(y=mx+b\), equivalently \(f(x)=c_0+c_1x\) with \(c_1\) the slope and \(c_0\) the intercept.
  • Degree 2 (Quadratic regression) is not nearly as common — now the regression becomes genuinely non-linear, and the fitted curve is not restricted to a straight line.
Fitting by least squares — the residual function

To calculate coefficients that take all data points into consideration, we use least squares, built around a residual function. For any point \((x_i,y_i)\) on the line, the residual (error) is:

\[ e_i = y_i - f(x_i) \]

For each point, the residual tells us the error between our estimate and the true data. To get the overall error, we can't just sum the residuals directly, since errors can be positive or negative and would cancel out — so instead we square them and sum, giving the familiar sum-of-squares error. We want this sum to be as small as possible — we minimize it.

Setting up quadratic regression's normal equations

For the quadratic model \(y=a_0+a_1x+a_2x^2\), minimizing the sum of squared residuals over \(n\) known data points leads to a system of 3 normal equations in \(a_0,a_1,a_2\):

\[ \begin{aligned} na_0 + a_1\textstyle\sum x_i + a_2\sum x_i^2 &= \sum y_i\\ a_0\textstyle\sum x_i + a_1\sum x_i^2 + a_2\sum x_i^3 &= \sum x_iy_i\\ a_0\textstyle\sum x_i^2 + a_1\sum x_i^3 + a_2\sum x_i^4 &= \sum x_i^2y_i \end{aligned} \]

Logistic Regression

The first classification algorithm of the course — despite the name "regression." This lecture builds the sigmoid function up from scratch, connects it to the language of odds and log-odds used throughout statistics, derives its cost function, and trains it by hand via stochastic gradient descent.

4.1 The Sigmoid Function

The single most important fact about Logistic Regression

Logistic regression is not a regression — it is a classification learning algorithm. The name comes from statistics, because its mathematical formulation resembles linear regression's.

Definition — the standard logistic (sigmoid) function

\[ f(x) = \frac{1}{1+e^{-x}} \]

\(e\) is the base of the natural logarithm (Euler's number); \(e^x\) is also called \(\exp(x)\). The natural logarithm (\(\ln\)) and \(e^x\) are inverse operations. The sigmoid is an S-shaped curve that takes any real-valued number and maps it into a value between 0 and 1 — but never exactly at those limits.

def sigmoid(x):
    return 1.0 / (1 + np.exp(-x))
# Ex: exp(0) = 1, sigmoid(0) = 0.5

As \(x\to\infty\), the probability approaches 1; as \(x\to-\infty\), it approaches 0.

Reading the sigmoid's graph for classification

Interpreting \(f(x)\): if it's \(\ge\) the threshold 0.5, we say the class of \(x\) is 1 (positive); otherwise, 0 (negative).

4.2 How Logistic Regression Predicts Probabilities

Modelling the probability of a class

Logistic regression models the probability of the "default" class. Example: modelling a person's status (\(Y\)) as rich (1) or poor (0) from income (\(X\)) — the model gives \(P(\text{status}=\text{rich}\mid\text{income})\). Generally: \(P(X)=P(Y=1\mid X)\) — the probability that output \(y\) is 1, given input \(X\).

The sigmoid function is \(P(Y=1\mid X) = \dfrac1{1+e^{-z}}\), where the output can be directly interpreted as the estimated probability. (E.g. output 0.8 means an estimated 80% chance of the event.) Here \(z\) is a linear combination of input features and weights: \(z=B_0+B_1x\).

The full equation, and what each term means

Logistic regression uses an equation much like linear regression — inputs \(x\) are combined linearly using weights/coefficients — but the key difference is that the modelled output is binary (0 or 1), not a numeric value:

\[ y = \frac{e^{B_0+B_1x}}{1+e^{B_0+B_1x}} \]

\(y\) is the predicted output, \(B_0\) is the bias/intercept, \(B_1\) is the coefficient for input \(x\). Each input column has an associated \(B\) coefficient that must be learned from training data.

4.3 Odds and Log-Odds

Definitions

Odds represent the ratio of the probability of success to the probability of failure. If \(P\) is the probability of success and \(Q=1-P\) the probability of failure:

\[ O = \frac{P}{Q} = \frac{P}{1-P} \]

Log-odds (or logit) is the natural log of the odds: \(\text{logit}(O)=\ln(P/Q)\).

Worked Example Numerical

If the probability of winning a game is 0.6: odds \(=0.6/0.4=1.5\). Log-odds \(=\ln(1.5)=0.405\).

Why transform odds into log-odds at all?
  • It transforms the odds ratio onto a linear scale, making it amenable to modelling with linear-regression-style techniques.
  • Log-odds range from \(-\infty\) to \(+\infty\) (unlike probability, bounded in \([0,1]\), or odds, bounded in \([0,\infty)\)).
  • Changes in log-odds are more interpretable than changes in raw probability, especially for binary outcomes.
Deriving why ln(odds) = z — the key algebraic link

The sigmoid function can be written \(P(x)=\dfrac{e^z}{1+e^z}\) (an equivalent form of \(\frac{1}{1+e^{-z}}\), obtained by multiplying top and bottom by \(e^z\)). So \(1-P(x) = \dfrac{1}{1+e^z}\). Substituting into the log-odds expression:

\[ \ln\left(\frac{P(x)}{1-P(x)}\right) = \ln\left(\frac{e^z/(1+e^z)}{1/(1+e^z)}\right) = \ln(e^z) = z \]

Since \(z=B_0+B_1x\) is linear in the inputs, this gives the central identity of logistic regression:

\[ \ln(\text{odds}) = B_0+B_1x \]

Exponentiating both sides (using that \(\ln\) and \(e^x\) are inverse operations): \(\text{odds}=e^{B_0+B_1X}\). So the model is a linear combination of the inputs — but that linear combination relates to the log-odds of the default class, not the probability directly. This transform connecting the linear equation to the probabilities is called the link function (here, the logit link function).

Learning the model — the intuition for Maximum Likelihood

The coefficients must be estimated from training data using maximum-likelihood estimation. The best coefficients would predict a value very close to 1 for the default class, and very close to 0 for the other class. Intuitively, a search procedure seeks coefficient values that minimize the error in the predicted probabilities — a minimization algorithm optimizes the coefficients, often implemented via an efficient numerical optimization routine, or (as this course does) from scratch using gradient descent.

4.4 Cost Functions, and Types of Slope

Types of slope, for the line y = b₀ + b₁x
  • Positive slope — \(y\) increases as \(x\) increases; the line runs "uphill" left to right. Example: slope 5, intercept 2 — when \(x\) increases by 1, \(y\) increases by 5.
  • Negative slope — \(y\) decreases as \(x\) increases; runs "downhill." Example: slope −0.4, intercept 7.2 — when \(x\) increases by 1, \(y\) decreases by 0.4.
  • Zero slope — \(y\) doesn't change; a horizontal line. Example: slope 0, intercept −4. A slope of zero moves only left/right, never up/down.
  • Vertical lines are problematic — no change in \(x\) means the slope formula divides by zero, so the slope is undefined. Some call this "infinite slope"; since we can't tell if it's \(+\infty\) or \(-\infty\), the term "no slope" is also common (and, admittedly, a little confusing).
Cost function vs. loss function — the distinction to remember

Loss function — measures how good the model is at predicting the expected outcome for a single sample, compared to its actual value. If loss is low, the model gives good results for that sample.

Cost function — the average of all the loss function values, across the whole dataset. Both need to be minimized to improve model performance; in casual usage the two terms are often used interchangeably, referring to the same overall goal (minimizing the error between actual and predicted outcomes).

Visualizing the cost function for Linear Regression

For Linear Regression, many different lines are possible (different slopes and intercepts) — which one is "right"? We use Mean Squared Error (MSE) as the criterion: the sum of squared differences between prediction and true value, collapsed into a single number. MSE is the cost function for linear regression. The line with the minimum MSE represents the best-fitting relationship between \(X\) and \(Y\); once found, that line is used to predict \(Y\) for new inputs.

4.5 Deriving the Logistic Regression Cost Function

Setup

The model predicts the probability that an input belongs to a class, via the sigmoid: \(\text{prediction}=\sigma(z)\), \(z=b_0+b_1x_1+b_2x_2\). The true label \(y\) is either 0 or 1.

The cost function — negative log-likelihood (cross-entropy)

For a single training example \((x_1,x_2,y)\), the cost is defined as:

\[ \text{Cost}(b_0,b_1,b_2) = -y\cdot\log(\text{prediction}) - (1-y)\cdot\log(1-\text{prediction}) \]

Reading this: when \(y=1\), the cost reduces to just \(-\log(\text{prediction})\) — small when the prediction is close to 1 (correct), huge when it's close to 0 (badly wrong). When \(y=0\), it reduces to \(-\log(1-\text{prediction})\) — small when the prediction is close to 0, huge when close to 1. Either way, confidently wrong predictions are punished heavily.

Taking the partial derivative of the cost with respect to \(b_0,b_1,b_2\), and using the fact that the sigmoid's own derivative is \(\sigma(z)(1-\sigma(z))\), the chain rule collapses beautifully:

\[ \frac{\partial\,\text{Cost}}{\partial b_j} = (\text{prediction}-y)\cdot x_j \]

— a remarkably clean result: the gradient is just the error, scaled by the input, with no leftover sigmoid-derivative term at all (it cancels out algebraically against the \(\log\) in the cost function).

An inconsistency in the slides, worth understanding rather than memorising blindly

Your slides state the update rule as:

\[ b = b + \alpha\cdot(y-\text{prediction})\cdot\text{prediction}\cdot(1-\text{prediction})\cdot x \]

This extra \(\text{prediction}\cdot(1-\text{prediction})\) factor does not actually belong to the cross-entropy cost function just derived above (whose gradient is the clean \((\text{prediction}-y)\cdot x\), with no such factor). Where does it come from? If you instead used plain squared error as the cost — \(\frac12(y-\text{prediction})^2\), the same style of cost used for linear regression throughout this course — differentiating it through the sigmoid via the chain rule does produce exactly this extra \(\text{prediction}(1-\text{prediction})\) factor (the sigmoid's own derivative). So the update rule as written matches training logistic regression with squared-error loss, not the cross-entropy loss stated just above it.

It gets more tangled still: checking the actual worked numbers in Section 4.6 below against this stated formula shows the real arithmetic used doesn't include the \((1-\text{prediction})\) factor either — it matches simply \(\alpha\cdot\text{error}\cdot\text{prediction}\cdot x\). 4.7 Regression vs. Classification Problems

The general distinction, beyond just Linear/Logistic Regression

Variables can be characterized as quantitative or qualitative (categorical).

  • Quantitative variables take on numerical values — e.g. a person's age, height, or income; the value of a house; the price of a stock.
  • Qualitative variables take on values in one of \(K\) different classes/categories — e.g. the brand of product purchased (A, B, or C); whether a person defaults on a debt (yes/no); a disease diagnosis.

We tend to call problems with a quantitative response regression problems, and problems with a qualitative response classification problems. This is exactly why Logistic Regression — despite its name — is a classification technique: its response variable (which class?) is qualitative, not quantitative.

2. Accuracy — "what proportion of all predictions were correct?"

k-Nearest Neighbors (k-NN)

The first genuinely non-parametric algorithm covered in depth — k-NN doesn't learn an equation at all. It just remembers the training data, and at prediction time, looks around for the most similar examples it has on file.

6.1 How k-NN Works

Definition and key vocabulary
  • k-NN is a nearest neighbor learning method.
  • It's called a lazy learner algorithm — it does not learn from the training data immediately; instead it stores the dataset, and only acts on it at classification time.
  • It's also called instance-based / memory-based learning — it needs memory to store the dataset during training, and predicts a test instance's class only when a new instance actually arrives, delaying all real processing until then.
  • It is non-parametric and supervised. It handles both classification and regression, though it's most commonly used for classification.
The core principle

Predict the label of a new (test) data point by considering the labels of its nearest neighbours. \(k\) is the number of nearest neighbours considered. E.g. with \(k=3\): out of all \(n\) distances computed during testing, only the 3 nearest are used for the prediction.

Algorithm 4.1: k-NN, formally

Inputs: Training dataset \(T\), distance metric \(d\), test instance \(t\), number of nearest neighbours \(k\). Output: predicted class or category.

  1. For each instance \(i\) in \(T\), compute the distance between \(t\) and \(i\) using the distance metric.
    • Continuous attributes — Euclidean distance: \(\text{dist}((x_1,y_1),(x_2,y_2))=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}\)
    • Categorical (binary) attributes — Hamming Distance: if the two instances' values are the same, \(d=0\); otherwise \(d=1\).
  2. Sort the distances in ascending order and select the first \(k\) nearest training instances.
  3. Predict the class by majority voting (if the target attribute is discrete) or the mean (if continuous) of the \(k\) selected nearest instances.
General steps, in plain language
  1. Selecting the optimal value of K — the number of nearest neighbours to consider.
  2. Calculating distance — measure similarity between the target and every training point (Euclidean, Manhattan, or Minkowski distance).
  3. Finding nearest neighbours — the \(k\) points with the smallest distances to the target.
  4. Voting for classification, or taking the average for regression.
Applications
  • Recommendation systems (Amazon, Netflix)
  • Spam detection
  • Customer segmentation
  • Speech recognition
Advantages / Disadvantages

+ Easy to implement, no training required, few hyperparameters, flexible.

− Doesn't scale well to large datasets; struggles as the number of features grows; prone to overfitting.

Formalising the distance metrics, in general

Three common distance measures between two points \(P(x_1,y_1)\) and \(Q(x_2,y_2)\) in 2D:

MetricFormulaIntuition
Euclidean\(d_E(P,Q)=\sqrt{(x_1-x_2)^2+(y_1-y_2)^2}\)Straight line ("as the crow flies") between P and Q.
Manhattan\(d_M(P,Q)=|x_1-x_2|+|y_1-y_2|\)Path along the axes, like city blocks — horizontal + vertical.
Minkowski\(d_p(P,Q)=\big(|x_1-x_2|^p+|y_1-y_2|^p\big)^{1/p},\ p\ge1\)A generalised distance, parameterised by \(p\).

Minkowski distance is a family that contains the other two as special cases: \(p=1\to\)Manhattan distance, \(p=2\to\)Euclidean distance, \(p\to\infty\to\)Chebyshev (\(L_\infty\)) distance. Choosing \(p\) lets you tune how heavily large individual coordinate differences are penalised relative to many small ones.

Three factors that strictly affect k-NN's performance
  1. Number of nearest neighbours (k) — too small a \(k\) makes the model sensitive to noise (overfits, following every quirk of individual points); too large a \(k\) oversmooths and can wash out real local structure (underfits), and starts pulling in points that aren't really "nearby" in any meaningful sense.
  2. Distance metric — should be chosen based on the type of data; it must not be dominated by whichever feature happens to have larger raw numbers (a bigger number in the training data doesn't mean it deserves more importance — hence the need for scaling, Section 6.3).
  3. Decision rule — how the k neighbours' values get combined (majority vote, simple average, or weighted, Section 6.6). k-NN works better in low dimensions, because in high dimensions, the notion of "nearness" itself becomes less meaningful — with enough features, most points end up roughly equidistant from each other (a symptom of the so-called "curse of dimensionality").

6.6 Weighted k-NN

The idea

In ordinary k-NN, all \(k\) neighbours count equally in the vote/average. In Weighted k-NN, the \(k\) closest neighbours are given higher weight in the decision than neighbours that are farther away (but still among the \(k\) selected) — a closer neighbour has more influence than a farther one.

If you don't assign weights at all, it works like ordinary k-NN — every neighbour weighted equally. If you do assign weights, give more weight to points that are nearer.

The exact Weighted k-NN algorithm, step by step

Inputs: Training dataset \(T\), distance metric \(d\), weighting function \(w(i)\), test instance \(t\), number of neighbours \(k\). Output: predicted class or category.

  1. For each instance in \(T\), compute the distance to \(t\) (Euclidean for continuous attributes; Hamming for binary/categorical — identical to ordinary k-NN's Step 1).
  2. Sort distances ascending; select the first \(k\) nearest training instances.
  3. Predict the class by weighted voting, computed as:
    • Compute the inverse of each of the \(k\) selected distances: \(w_i=1/d_i\).
    • Find the sum of these inverses.
    • Compute each neighbour's weight by dividing its inverse distance by that sum — each weight is effectively a "vote," but a fractional one, for its neighbour's class.
    • Add up the weighted votes for each class, and predict the class with the maximum total weight.

This is the precise mechanism behind Section 6.6's general description: closer neighbours (smaller \(d_i\), so larger \(1/d_i\)) end up with proportionally larger weights, and therefore more say in the final vote, than neighbours near the edge of the \(k\)-neighbourhood.

Algorithm of Weighted k-NN

Input: Training dataset \(T\), distance metric \(d\), weight function \(w\), test instance \(t\), number of neighbours \(k\). Output: predicted class or category.

The first two steps are identical to ordinary k-NN (compute distances, sort and select the \(k\) nearest). The difference is in the final step: instead of a plain majority vote or simple average, each of the \(k\) selected neighbours contributes a weight — commonly the inverse of its distance (\(w=1/d\), or \(1/d^2\)) — so nearer neighbours pull the final decision more strongly than farther ones.

What Lecture 6 adds to your toolkit

k-NN is the clearest possible illustration of "non-parametric": there's no equation to learn, no coefficients to estimate — just a stored dataset and a distance calculation done fresh at prediction time. Its Achilles' heel is exactly what its strength as a distance-based method implies: feature scaling and the choice of \(k\) (best chosen via cross-validation) matter enormously, in a way they simply don't for parametric models like Linear Regression.

7.1 Probability Foundations

What is probability-based learning?

Learning combines prior knowledge (prior probabilities) with observed data. Instead of giving one single, fixed answer, this approach calculates the likelihood of different possible results — using probability theory to describe randomness, uncertainty, and noise, in order to predict future events. It's a tool for modelling large datasets.

Marginal, Joint, and Conditional probability
  • Joint probability — the probability of two events occurring simultaneously.
  • Marginal probability — the probability of an event, irrespective of the outcome of another variable.
  • Conditional probability — the probability of one event occurring in the presence of a second event.

Joint probability of Male AND Pass: \(P(\text{Male}\cap\text{Pass})=40/100=0.40\). Similarly \(P(\text{Female}\cap\text{Pass})=30/100=0.30\).

Marginal probability of Male: \(P(\text{Male})=50/100=0.50\). Marginal probability of passing: \(P(\text{Pass})=70/100=0.70\).

Conditional probability: since we already know the student is male, we only consider the 50 males — 40 of them passed. \(P(\text{Pass}\mid\text{Male})=40/50=0.80\).

The relationship linking all three

\[ P(M\cap P) = P(P\mid M)\times P(M) \]

i.e. Joint = Conditional × Marginal. Joint probability is symmetrical: \(P(M\cap P)=P(P\cap M)\). But conditional probability is NOT symmetrical: \(P(P\mid M)\ne P(M\mid P)\) in general — confirm from the table: \(P(P\mid M)=40/50=0.80\), quite different from \(P(M\mid P)=40/70=0.571\).

An alternate way to calculate conditional probability — this IS Bayes' Rule

One conditional probability can be calculated using the other conditional probability:

\[ P(A\mid B) = \frac{P(B\mid A)\cdot P(A)}{P(B)} \qquad\text{(and symmetrically)}\qquad P(B\mid A) = \frac{P(A\mid B)\cdot P(B)}{P(A)} \]

This is useful when the joint probability is hard to calculate directly (which is most of the time), or when the reverse conditional probability is available or easier to compute. This is Bayes' Rule (or Bayes' Theorem), named for Reverend Thomas Bayes, credited with first describing it.

Prior Probability

The probability of a class occurring before any evidence (features) is observed. E.g. if 100 samples belong to Class A and 50 to Class B, the class prior for A is \(100/150\).

Posterior Probability

The probability of an event/hypothesis \(A\) occurring after observing some evidence \(B\) — i.e. \(P(A\mid B)\).

Bayesian Learning

Describes and represents knowledge in an uncertain domain, mainly using probability to reason about it. Uses Bayes theorem to infer unknown parameters. Useful in reasoning and diagnosis, handling missing data, and estimating uncertainty in predictions.

7.2 Bayes' Theorem

What is Bayes Theorem?

A fundamental concept in probability theory, playing a crucial role in many ML algorithms. It provides a way to update a probability based on new evidence, allowing us to infer belief in a hypothesis (represented by a prior, \(P(A)\)) based on new evidence.

Derivation, from the definition of conditional probability

From the definition of conditional probability, for two events \(A\) and \(B\):

\[ P(A\mid B) = \frac{P(A\cap B)}{P(B)},\ P(B)\ne0 \qquad P(B\mid A) = \frac{P(B\cap A)}{P(A)},\ P(A)\ne0 \]

Since the joint probability is symmetric, \(P(B\cap A)=P(A\cap B)\), and:

\[ P(A\cap B) = P(A\mid B)P(B) = P(B\mid A)P(A) \]

Rearranging gives Bayes' Theorem:

\[ P(A\mid B) = \frac{P(B\mid A)\,P(A)}{P(B)},\qquad P(B)\ne0 \]

Bayes' theorem is also known as the formula for the probability of "causes" — it describes the probability of occurrence of an event related to any condition, and is a special case of conditional probability.

Naming every term — worth knowing cold
  • \(P(A\mid B)\) — the posterior probability (probability of class \(A\) given feature \(B\)).
  • \(P(B\mid A)\) — the likelihood (probability of feature \(B\) given class \(A\)).
  • \(P(A)\) — the prior probability of class \(A\).
  • \(P(B)\) — the evidence (probability of feature \(B\)).

Posterior = Likelihood × Prior / Evidence

The three components, in sequence
  1. Prior probability — your initial belief about how likely an outcome is, before seeing evidence. E.g. if 30% of emails in a dataset are spam, the prior probability any new email is spam is 0.3.
  2. Likelihood — how probable the observed evidence is, given a particular outcome. E.g. the probability of seeing the word "discount" in spam emails vs. non-spam emails.
  3. Posterior probability — your updated belief after considering the evidence — the final probability used to make a decision. This is exactly what the Naive Bayes classifier calculates to decide which class a data point belongs to.
How Bayes' Theorem applies to classification
  1. Start with prior probabilities for each class, from the training data.
  2. Calculate the likelihood of observing the specific features in each class.
  3. For a new data point, compute the posterior probability for each possible class.
  4. Assign the data point to the class with the highest posterior probability.
Worked Example — completing the rain/cloudy problem Numerical

Suppose \(P(\text{cloudy})=0.4\), \(P(\text{rain})=0.2\), and \(P(\text{cloudy}\mid\text{rain})=0.85\). If it's cloudy today, what's the probability it will rain?

$$P(\text{rain}\mid\text{cloudy}) = \frac{P(\text{cloudy}\mid\text{rain})\times P(\text{rain})}{P(\text{cloudy})} = \frac{0.85\times0.2}{0.4} = 0.425$$
P(rain | cloudy) = 0.425 (42.5%)
Complement rules, useful for filling in missing pieces

\(P(\text{not }A)=1-P(A)\). If we have \(P(\text{not }B\mid\text{not }A)\), then \(P(B\mid\text{not }A)=1-P(\text{not }B\mid\text{not }A)\).

7.3 The Naive Bayes Classifier

Definition

Naive Bayes is a simple and powerful supervised algorithm for predictive modelling, based on Bayes theorem, used for classification problems — both binary and multiclass. It's easiest to understand with binary or categorical inputs.

Why is it called "naive"?

It's called naive Bayes (or "idiot Bayes") because the probability calculation for each hypothesis is simplified to make it tractable. Rather than computing the joint \(P(d_1,d_2,d_3\mid h)\) directly, the attributes are assumed to be conditionally independent given the target value, and calculated as \(P(d_1\mid h)\times P(d_2\mid h)\times\cdots\). This is a strong assumption, most unlikely to be exactly true in real data — attributes usually do interact. Nevertheless, the approach performs surprisingly well even where this assumption clearly doesn't hold.

Concretely: to predict whether a person will Play based on Weather=Sunny, Temperature=Mild, Humidity=High — Naive Bayes assumes that once we know whether the person will Play or Not, Weather, Temperature, and Humidity are independent of one another. Counting how many times each attribute co-occurs with each class is the main learning idea.

Working of the Naive Bayes Classifier — the four steps
  1. Convert the given dataset into frequency tables.
  2. Generate a Likelihood table by finding the probabilities of the given features.
  3. Use Bayes theorem to calculate the posterior probability.
  4. The class with the higher probability is the predicted class.

7.5 Python Implementation

Building Naive Bayes from scratch, conceptually

Using the same Play Tennis-style idea, but simplified to one feature (Weather) with data [('Sunny','Yes'),('Overcast','Yes'),('Rainy','No'),('Sunny','No')]:

data = [('Sunny','Yes'), ('Overcast','Yes'), ('Rainy','No'), ('Sunny','No')]
yes_count = sum(1 for w,l in data if l=='Yes')
no_count  = sum(1 for w,l in data if l=='No')
total = len(data)
prob_yes, prob_no = yes_count/total, no_count/total

prob_given_yes = {'Sunny':0,'Overcast':0,'Rainy':0}
prob_given_no  = {'Sunny':0,'Overcast':0,'Rainy':0}
for weather, label in data:
    if label=='Yes': prob_given_yes[weather]+=1
    elif label=='No': prob_given_no[weather]+=1
for w in prob_given_yes:
    prob_given_yes[w] /= yes_count
for w in prob_given_no:
    prob_given_no[w]  /= no_count

def predict(weather):
    p_yes = prob_yes*prob_given_yes[weather]
    p_no  = prob_no*prob_given_no[weather]
    return 'Yes' if p_yes>p_no else 'No'

print(predict('Sunny'))

This mirrors exactly the 4-step recipe from Section 7.3: count → convert to probabilities (priors and likelihoods) → combine via Bayes' rule → compare and pick the larger.

7.6 Gaussian Naive Bayes

Definition

In Gaussian Naive Bayes, the predictors take continuous values, assumed to be sampled from a Gaussian (Normal) Distribution.

An important distinction — which variant to use

Case 1 — Categorical feature (e.g. Blood Pressure category: Low, Normal, High) → use ordinary (Categorical) Naive Bayes, possibly with Laplace smoothing. Case 2 — Numerical feature (e.g. actual blood pressure: 120, 125, 130, 140, 145, 150) → use Gaussian Naive Bayes. Even though the training values form a finite/discrete set of numbers, BP is conceptually a continuous numerical variable — so Gaussian NB models its underlying distribution instead of just counting frequencies.

7.7 Text Classification with Naive Bayes

Why text classification matters, and where it shows up

Assigning subject categories, topics, or genres; spam detection; authorship identification; age/gender identification; language identification; sentiment analysis.

The formal setup

Input: a document \(d\); a fixed set of classes \(C=\{c_1,c_2,\dots,c_J\}\). Output: a predicted class \(c\in C\). Notation: \(\gamma(d)=c\) represents the classifier — \(\gamma()\) is the classifier, \(d\) the document, \(c\) the assigned class. (E.g. the "mark as spam" button in Gmail is exactly this \(\gamma(d)\) being invoked.)

The representation: Bag of Words

Naive Bayes text classification relies on a very simple document representation — the bag of words: ignore word order and sentence construction entirely, and treat every document as just the set (with counts) of words it contains. Since text can't be fed directly into a classifier, and documents vary hugely in length and word combinations, we use word occurrence counts (term frequency) to build feature vectors.

$$P(\text{comp.graphics}\mid\text{GPU}) = P(\text{GPU}\mid\text{comp.graphics})\times\frac{P(\text{comp.graphics})}{P(\text{GPU})}$$ $$P(\text{comp.graphics}) = \frac34=0.75 \qquad P(\text{GPU}) = \frac34=0.75 \qquad P(\text{GPU}\mid\text{comp.graphics})=\frac23=0.66$$ $$P(\text{comp.graphics}\mid\text{GPU}) = 0.66\times\frac{0.75}{0.75}=0.66$$
0.66 > 0.5 → predict this text is about computer graphics

Question: which tag does "A very close game" belong to?

Feature engineering: word frequencies (bag of words)

Ignore word order; treat each document as a set of word counts. To compare tags, the shared denominator (evidence) can simply be discarded — we only need to know which numerator is bigger.

The zero-probability problem

Directly calculating \(P(\text{"a very close game"}\mid\text{Sports})\) is impossible — this exact sentence never appears in the training data, so this probability is 0. This is exactly why the "naive" assumption is useful: instead of whole sentences, treat every individual word as independent, so "this was a fun party" is treated the same as "party fun was this." Individual words do recur in the training data, even if whole sentences don't.

Priors $$P(\text{Sports})=\frac35=0.6 \qquad P(\text{Not Sports})=\frac25=0.4$$
Likelihoods — hit the zero problem again

\(P(\text{game}\mid\text{Sports})\): "game" appears 2 times across the Sports texts, which total 11 words → \(2/11\). But \(P(\text{close}\mid\text{Sports})=0\) ("close" never appears in a Sports text), and similarly \(P(\text{very}\mid\text{Not Sports})=0\), \(P(\text{game}\mid\text{Not Sports})=0\). Multiplying these into the product makes the whole likelihood collapse to zero — the well-known problem with plain Maximum Likelihood Estimation (MLE) on sparse data. Solution: Laplace (add-1) smoothing (Section 7.8).

Applying Laplace smoothing

Add 1 to every count, and add the vocabulary size \(V\) to every denominator (so probabilities never exceed 1). Vocabulary here: {a, great, game, the, election, was, over, very, clean, match, but, forgettable, it, close} — \(V=14\) unique words. Sports has 11 total word-tokens; Not Sports has 9.

WordP(word|Sports), smoothedP(word|Not Sports), smoothed
a(2+1)/(11+14) = 0.12(1+1)/(9+14) = 0.087
very(1+1)/(11+14) = 0.08(0+1)/(9+14) = 0.0435
close(0+1)/(11+14) = 0.04(1+1)/(9+14) = 0.087
game(2+1)/(11+14) = 0.12(0+1)/(9+14) = 0.0435
Combine — prior × product of likelihoods $$P(\text{Sports}\mid\text{"a very close game"}) \propto 0.6\times0.12\times0.08\times0.04\times0.12 \approx 2.76\times10^{-5}$$ $$P(\text{Not Sports}\mid\text{"a very close game"}) \propto 0.4\times0.087\times0.0435\times0.087\times0.0435 \approx 5.72\times10^{-6}$$
P(Sports|...) is about 5× larger → the classifier tags "A very close game" as Sports
Handling unknown words

A word that appears in test data but never appeared in any training document, in any class, is an unknown word. Solution: simply ignore it — remove it from the test document and don't include any probability for it. E.g. testing "A clean tough game": "tough" never appeared in training, so treat the test sentence as "A clean game" instead. (This is different from a word that appears in some classes but not others — for that case, keep the word and let Laplace smoothing handle the zero, rather than discarding it.)

Finding the vocabulary size V

\(V\) is the number of unique words in the training data — the union of all word types across all classes, not just the words in one class.

Advanced techniques to improve basic Naive Bayes text classification
  • Removing stop words — common words that add nothing to classification (a, able, either, else, ever, ...). "The election was over" → "election over"; "a very close game" → "very close game."
  • Lemmatizing words — grouping different inflections of the same word together (election, elections, elected → all counted as the same word appearing more times).
  • Using n-grams — instead of counting single words, count sequences of words (e.g. "clean match," "close election") to capture some of the word-order information that bag-of-words otherwise throws away.

7.8 Laplace Smoothing — a Complete Worked Walkthrough

The simple idea

Instead of allowing any word's probability to become exactly zero, add 1 to every count. To keep the result a valid probability (never exceeding 1), add the vocabulary size \(V\) to the denominator too:

\[ P(\text{word}\mid\text{class}) = \frac{\text{count}(\text{word, class})+1}{\text{total words in class}+V} \]

Step 2 — Likelihood, for Spam (no smoothing needed here)

Words in the new email: win, free, prize. Counting across the 5 Spam emails:

Step 2b — Likelihood for Ham hits the zero-probability problem

None of "win," "free," "prize" occur in any of the 5 Ham emails — so a direct calculation gives \(P(\text{win}\mid\text{Ham})=P(\text{free}\mid\text{Ham})=P(\text{prize}\mid\text{Ham})=0\), and the whole product collapses to 0.

Applying Laplace smoothing to fix this

Suppose the full vocabulary contains \(V=18\) unique words. Ham has 5 total word-tokens.

$$P(\text{win}\mid\text{Ham}) = \frac{0+1}{5+18} = \frac1{23}\approx0.0435$$

The same smoothed value applies to "free" and "prize" (each also has 0 occurrences in Ham):

$$P(\text{win, free, prize}\mid\text{Ham}) = 0.0435^3 \approx 0.0000822$$
Step 3 — Posterior probability, both classes $$P(\text{Spam})\times P(\text{words}\mid\text{Spam}) = 0.5\times0.288 = 0.144$$ $$P(\text{Ham})\times P(\text{words}\mid\text{Ham}) = 0.5\times0.0000822 \approx 0.0000411$$
P(Spam|...) = 0.144 ≫ P(Ham|...) ≈ 0.0000411 → classify "Win free prize" as SPAM
Generalising Laplace smoothing — three ways to estimate a conditional probability

If even one conditional probability in the Naive Bayes product is zero, the entire expression becomes zero — this is exactly the failure mode Section 7.7 ran into. There's a spectrum of fixes, from no correction at all to a fully tunable one:

MethodFormula
Original (no smoothing)\(P(A_i\mid C) = \dfrac{N_{ic}}{N_c}\)
Laplace (add-1)\(P(A_i\mid C) = \dfrac{N_{ic}+1}{N_c+c}\)
m-estimate\(P(A_i\mid C) = \dfrac{N_{ic}+mp}{N_c+m}\)

where \(N_{ic}\) is the count of attribute value \(A_i\) within class \(C\), \(N_c\) is the total count for class \(C\), \(c\) is the number of classes, \(p\) is a prior probability, and \(m\) is a tunable parameter.

Laplace smoothing is exactly the special case of the m-estimate where \(m=c\) and \(p=1/c\) (a uniform prior across all classes) — so everything in Section 7.7's spam/ham example is really just the m-estimate with these particular settings. The general m-estimate lets you dial in a different (non-uniform) prior \(p\), and control how strongly it pulls the estimate away from the raw counts via \(m\): a larger \(m\) means more smoothing (leaning more on the prior), a smaller \(m\) means trusting the observed counts more.

The complete Naive Bayes flow, summarised end to end

Training Emails → count Spam and Ham emails → calculate Prior → count word frequencies per class → calculate Likelihood (with Laplace smoothing wherever needed) → for a new email, multiply Prior × Likelihood for each class → get the Posterior for each class → compare → the higher probability wins.

What Lecture 7 — and this whole course — adds up to

Naive Bayes closes the loop on a theme running through every lecture in this guide: start from a simple, honest assumption (here, feature independence given the class), derive exactly what that assumption implies mathematically, and then confront where the assumption visibly breaks (the zero-probability problem) with a principled fix (Laplace smoothing) rather than throwing the whole model out. The same pattern — simple model, honest derivation, a known failure mode, and a practical fix — is exactly what made Linear Regression's gradient descent, Logistic Regression's cost function, and k-NN's feature scaling all work the way they do.
